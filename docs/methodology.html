3.1 System Overview

The proposed framework addresses the central gap in computational oncology: the absence of a system that can reason over conflicting multi-omics signals the way a trained oncologist does, applying explicit causal logic to determine which evidence layer should dominate when genomic, transcriptomic, pathway, and pharmacological signals disagree. Drug resistance causes more than 90% of deaths in patients receiving targeted cancer therapy [1], yet existing deep learning frameworks reconcile conflicting data layers through learned weights that are biologically opaque [2,3], and LLM-based multi-agent systems resolve conflicts through social negotiation rather than principled rules, producing sycophantic convergence and hallucinated biomarkers [4].

This work introduces a Decentralised Multi-Agent System (DMAS) in which four specialist LLM agents — each operating on a distinct omics modality — independently analyse a (cell line, drug) pair, submit structured evidence packs, and engage in a two-round peer debate whose outcome is governed by an explicit biological axiom hierarchy. The system architecture is grounded in two established clinical practices: the Multidisciplinary Tumour Board (MDT), in which specialists from genomics, pathology, and pharmacology debate and synthesise conflicting clinical signals [5,6]; and the central dogma of molecular biology, which establishes that DNA-level structural alterations constitute the highest-fidelity evidence of drug-target interaction state [5,7].

The framework is implemented in Python using FastMCP for structured tool access, Google Vertex AI (Gemini 3.1 Flash Lite) as the LLM backend, and SQLite databases built from four publicly available bioinformatics resources. All agent data access is mediated through typed, schema-validated Model Context Protocol (MCP) tool calls, converting hallucination from a probabilistic failure mode into a detectable protocol violation: an agent cannot assert a mutation that the genomics server did not return [8,9].

Figure 1. Five-layer framework architecture. Data flows from public databases (Layer 1) through MCP-validated tool APIs (Layer 2) to specialist LLM agents (Layer 3), which engage in a two-round debate protocol (Layer 4), producing a structured output with a full audit trail (Layer 5).

3.2 Dataset Sources

The framework draws on four publicly available bioinformatics databases, selected to provide orthogonal evidence for drug sensitivity prediction. The use of multiple independent data sources is essential: single-omics data is inherently limited due to the low correlation (approximately 0.40) between mRNA and protein levels, and any single data modality captures only one dimension of the complex cellular state that determines drug response [2,3].

3.2.1 Genomic Data — CCLE/DepMap Somatic Mutations and Copy Number Variation

Somatic mutation profiles and copy number variation (CNV) data are sourced from the Cancer Cell Line Encyclopedia (CCLE) / DepMap project, maintained jointly by the Broad Institute and the Wellcome Sanger Institute [10]. The CCLE provides whole-exome sequencing mutation calls and CNV segment data for approximately 1,800 cancer cell lines spanning more than 30 cancer lineages. Driver mutations are annotated using the COSMIC Cancer Gene Census. For each mutation, the following fields are retained: cell line identifier, gene symbol, protein change (HGVS notation), mutation type (missense, nonsense, frameshift, splice site), driver status, and CIViC description.

CIViC enrichment. Mutation records are enriched at query time with drug-specific clinical evidence from the Clinical Interpretation of Variants in Cancer (CIViC) database [11]. CIViC provides structured evidence statements linking specific (gene, variant, drug) triples to resistance or sensitivity phenotypes, with evidence level ratings (A–E). The enrichment is performed via fuzzy drug-name normalisation: both the query drug and the CIViC drug field are reduced to uppercase alphanumeric strings, and a bidirectional containment check is applied. This allows, for example, Vemurafenib to match CIViC entries for PLX4032. CIViC evidence is the highest-priority signal within the T1 tier: a direct clinical evidence statement linking a mutation to a drug response supersedes all other genomic inference.

3.2.2 Transcriptomic Data — CCLE mRNA Expression

Gene expression data is sourced from the CCLE RNA-sequencing profiles, accessed via the DepMap public data portal [10]. Expression values are provided as log2(TPM+1) and are z-score normalised per gene across all cell lines to produce a cell-line-specific deviation score. A z-score below −2.0 is used as the transcriptional silencing threshold: a gene with z < −2.0 is considered functionally absent from the cell line's transcriptional programme, constituting a resistance mechanism for drugs that require target expression for efficacy. A z-score above +1.5 is used as an overexpression signal for expression-driven drugs. High-expression gene lists are pre-filtered at z ≥ 0.5 for pathway activity scoring and at z ≥ 1.0 for bypass gene detection.

3.2.3 Transcriptional Silencing Threshold

The T2 agent applies a silencing gate before reasoning over expression data. The threshold is defined as:

silencing(gene, cell_line) = 1  if  zgene(cell_line) < θ,  else 0

θ = −2.0  (module-level constant, SILENCING_THRESHOLD)

If silencing(target_gene, cell_line) = 1 → verdict forced to RESISTANT regardless of drug mechanism type

3.2.4 Pathway Data — KEGG Signalling Pathways

Signalling pathway gene membership and topology data are sourced from the Kyoto Encyclopedia of Genes and Genomes (KEGG) [12]. For each pathway, the complete gene membership list and intra-pathway roles (kinase, effector, transcription factor, etc.) are stored. Bypass routes — alternative signalling genes within the same pathway that can maintain downstream oncogenic signalling when a drug target is blocked — are curated from KEGG pathway diagrams and stored as directed (pathway_id, blocked_gene) → bypass_gene triplets. The pathway database covers 27 cancer-relevant signalling pathways including MAPK/ERK, PI3K/mTOR, EGFR, ABL, and apoptosis regulation.

3.2.5 Pharmacological Data — CTRPv2 / GDSC2 IC50 Profiles

Historical drug sensitivity data are sourced from two large-scale pharmacogenomic screens. The primary validation dataset uses the Cancer Therapeutics Response Portal v2 (CTRPv2), which measured drug sensitivity (area under the dose-response curve and IC50) across approximately 860 cancer cell lines and 481 compounds [13]. The development dataset uses GDSC2 (Genomics of Drug Sensitivity in Cancer, release 2), which provides IC50 profiles across 809 cell lines and 198 compounds measured at the Wellcome Sanger Institute [14]. IC50 values are converted to z-scores per drug across all tested cell lines: z < −0.5 is labelled SENSITIVE; z > +0.5 is labelled RESISTANT; |z| ≤ 0.5 is labelled UNCERTAIN. Drug target information and mechanism of action data are supplemented from ChEMBL [15].

3.3 Data Preprocessing and Database Construction

All four data sources are preprocessed into local SQLite databases to enable fast, offline tool calls without external API dependencies during inference. This design choice is essential for reproducibility and cost control: the SQLite-backed architecture allows the entire evaluation pipeline to be replicated without incurring external query costs or depending on third-party API availability.

3.3.1 Genomics Database (genomics.db)

Raw mutation calls from CCLE (MAF format) are filtered to retain only coding mutations with variant allele frequency ≥ 0.1. Each mutation is annotated with driver status using the COSMIC Cancer Gene Census v99. Protein changes are normalised by stripping the p. prefix and converting to uppercase (e.g. p.V600E → V600E) to enable fuzzy matching with CIViC variant nomenclature. CNV segment files are processed to gene-level copy number calls: amplification (segment mean > 2.0), hemizygous deletion (segment mean between 0.5 and 1.0), and homozygous deletion (segment mean < 0.5). The CIViC predictive evidence table is stored as a separate table (predictive_evidence) with columns for gene, variant (normalised), drug (normalised to uppercase alphanumeric), clinical significance, evidence level, and evidence statement. CIViC enrichment is performed at query time rather than at preprocessing time, enabling drug-specific filtering without pre-joining all possible triples.

3.3.2 Transcriptomics Database (transcriptomics.db)

CCLE RNA-sequencing data (log2 TPM+1) is z-score normalised per gene across all 1,800+ cell lines. The resulting z-scores and TPM values are stored in a flat expression table indexed on (cell_line, gene). A materialised view of high-expression genes (z > 0.5) is maintained per cell line to enable fast pathway activity queries without scanning the full expression table at inference time. The silencing threshold of z = −2.0 is stored as a module-level constant in axiom_rules.py, allowing the threshold to be adjusted without modifying query logic.

3.3.3 Pathway Database (pathways.db)

KEGG pathway data is retrieved via the KEGG REST API and stored in three tables: pathway_meta (pathway identifier, name, category), pathway_genes (pathway-gene membership with role and position annotations), and bypass_routes ((pathway_id, blocked_gene) → bypass_gene triplets). Bypass routes are curated from KEGG pathway diagrams by identifying genes that share downstream targets with the blocked gene but lie on independent upstream branches. A pathway activity score is computed at inference time as the fraction of pathway member genes with z-score ≥ 0.5 in the queried cell line; pathways with activity score below 0.4 are excluded from bypass analysis to avoid evaluating bypass routes in pathways that are not operationally active in the cancer context.

3.3.4 Pharmacology Database (pharmacology.db)

IC50 values from CTRPv2 and GDSC2 are converted to natural-log scale (ln IC50) and z-score normalised per drug across all tested cell lines using:

zdrug(cell_line) = ( ln IC50(cell_line, drug) − μdrug ) / σdrug

μdrug = mean of ln IC50 across all cell lines tested with that drug
σdrug = standard deviation of ln IC50 across those cell lines

Sensitivity label:  z < −0.5 → SENSITIVE   z > +0.5 → RESISTANT   |z| ≤ 0.5 → UNCERTAIN

Pre-computed sensitivity labels are stored alongside the raw z-scores to enable direct lookup. Drug target information and mechanism of action annotations are sourced from ChEMBL and stored in a drug_info table with fields for target genes (comma-separated HGNC symbols), mechanism class, and primary pathway. An LLM response cache (llm_cache.db) is maintained as a separate SQLite database, keyed on (model, prompt hash), to eliminate redundant LLM calls during iterative evaluation runs.

3.3.5 Case Construction and Label Derivation

The evaluation dataset consists of (cell line, drug) pairs with known sensitivity labels, drawn from CTRPv2 and GDSC2. Ground truth labels are derived from z-score normalised IC50 values using the thresholds above. The 40-case GDSC2 development set is stratified across five axiom tiers — eight cases per tier — to ensure that every component of the axiom hierarchy is exercised during evaluation. The 100-case CTRPv2 held-out validation set is drawn from five independent 20-case sets (sets 1–5), balanced for SENSITIVE and RESISTANT labels within each set. Three additional 10-case balanced sets (Sets A, B, C) are constructed specifically to stress-test the debate mechanism under conditions of conflicting multi-omics signals: Set A targets mutation-driven cases (T1 evidence available), Set B targets pathway/expression-driven cases (T2/T3 evidence available), and Set C targets mechanism-agnostic cases (T4 IC50 as the primary signal).

3.4 Framework Architecture

The framework is organised into five hierarchical layers, each with a distinct responsibility. The key architectural principle is separation of evidence access from evidence reasoning: agents never query databases directly. All data access is mediated through MCP tool calls, which return typed JSON and are logged, enabling post-hoc hallucination detection by cross-referencing agent citations against tool return values.

LayerComponentResponsibility
1 — Data Substrate4 × SQLite databasesStore pre-processed public omics data; serve as ground truth for hallucination detection
2 — MCP Servers4 × FastMCP instancesExpose typed tool APIs; validate inputs; return schema-conformant JSON
3 — Specialist Agents4 × LLM agentsFetch modality-specific evidence; reason over it; produce structured EvidencePacks
4 — Debate ProtocolDebateEngine + AxiomResolverCoordinate two-round peer debate; resolve conflicts via endorsement-weighted axiom logic
5 — Evaluation PipelineMetrics + RunLogger + Ablation runnerCompute AUROC/AUPRC/κ/ρ; log full audit trail; run ablation variants

The Orchestrator is the top-level coordinator. It receives a (cell line, drug) pair, dispatches all four agent analyze() calls concurrently using asyncio.gather(), collects the resulting EvidencePacks, and passes them to the DebateEngine. Concurrent agent execution is possible because agents share no state and make independent MCP tool calls; the shared LLM client enforces a rate limiter to prevent API quota exhaustion. After the debate protocol completes, the Orchestrator logs the ConsensusResult to the RunLogger and returns it to the caller.

3.5 Model Context Protocol Servers

The Model Context Protocol (MCP) [8,9] is a recently standardised protocol for connecting LLMs to external tools through typed, schema-validated function calls. Each MCP server in this framework is implemented using FastMCP, a Python library that converts decorated functions into MCP-compliant tool definitions. Agents interact with MCP servers through an async Client context manager, which serialises arguments, calls the server function, and deserialises the returned JSON. The key anti-hallucination property of this design is architectural: because every data claim an agent makes must originate from an MCP tool call, and because tool call inputs and outputs are logged by the RunLogger, it is possible to compute a per-case hallucination rate by checking whether each biomarker cited in an agent's EvidencePack was present in the tool responses for that case.

MCP as a structural anti-hallucination layer. In conventional LLM prompting, an agent can assert that a mutation exists, a gene is overexpressed, or an IC50 value is known without any verifiable connection to actual data. The MCP architecture converts this probabilistic failure mode into a detectable protocol violation: an agent cannot assert that BRAF V600E is present in a cell line unless the Genomics MCP server returned it. The guarantee is architectural, not probabilistic — the same design principle used in database transactions.

Genomics MCP Server

Exposes three tools: get_mutations(cell_line, gene, drug), which returns all somatic mutations for the (cell line, gene) combination, enriched at query time with CIViC predictive evidence specific to the queried drug; get_cnv(cell_line, gene), which returns copy number variation calls; and check_mutation_impact(gene, mutation), which returns driver status and CIViC descriptions for a specific variant. The CIViC enrichment pipeline applies bidirectional drug-name normalisation to maximise recall of relevant clinical evidence while minimising cross-drug contamination.

Transcriptomics MCP Server

Exposes three tools: get_expression(cell_line, gene), returning TPM and z-score for a specific gene; get_high_expression_genes(cell_line, z_threshold), returning all genes above the specified z-score threshold; and check_silencing(cell_line, gene), returning a boolean silencing flag with the threshold used. The silencing threshold (z = −2.0) is injected from axiom_rules.py to ensure consistency between the MCP server and the T2 agent's reasoning system prompt.

Pathway MCP Server

Exposes four tools: find_pathways_for_gene(gene), returning all KEGG pathways containing the gene; get_pathway_genes(pathway_id), returning the full gene membership of a pathway; check_bypass(pathway_id, blocked_gene), returning bypass gene candidates; and get_upstream_regulators(gene), returning upstream regulatory relationships. The bypass check is the critical T3 evidence call: it establishes whether an alternative signalling route exists that could maintain oncogenic signalling after the drug target is blocked.

Pharmacology MCP Server

Exposes three tools: get_ic50(cell_line, drug), returning the ln IC50, z-score, and pre-computed sensitivity label; get_drug_info(drug), returning target genes, mechanism class, and pathway; and get_sensitivity_profile(drug), returning population-level sensitivity distributions per mutation class. The pre-computed label is the primary T4 signal; the z-score is used by the Grounded Confidence Score (GCS) computation to quantify signal strength.

3.6 Specialist LLM Agents

Each specialist agent is implemented as a subclass of BaseAgent, which provides shared infrastructure for MCP tool calls, LLM prompt construction, response parsing, GCS computation, and RunLogger integration. All agents use the same LLM backend (Gemini 3.1 Flash Lite via Google Vertex AI), ensuring that performance differences between agents reflect modality-specific evidence availability rather than model capability differences. Each agent is assigned an evidence tier that reflects the biological priority of its modality.

T1  Genomics Agent

Modality: Somatic mutations, copy number variation, CIViC clinical evidence.

Decision logic: (1) Check for CIViC drug-specific annotation — if present, it is decisive. (2) If driver mutation present without CIViC: UNCERTAIN (functional consequence unknown without drug-specific evidence). (3) CNV amplification of target oncogene: SENSITIVE signal. (4) Homozygous deletion: RESISTANT. (5) Hemizygous deletion: UNCERTAIN (target still expressed at reduced level). (6) Wild-type in DB but gene present: UNCERTAIN with caveat that chromosomal fusions are not captured by point-mutation databases.

Key constraint: Wild-type status never defaults to RESISTANT. The absence of a driver mutation does not preclude drug activity through expression or IC50 mechanisms.

T2  Transcriptomics Agent

Modality: mRNA expression z-scores, high-expression gene context.

Decision logic: First classifies the drug's mechanism type: (A) Overexpression-driven — target expression level IS the signal (e.g. HER2 inhibitors); (B) Mutation-driven — expression level of the target gene is NOT predictive, downstream pathway activity is assessed instead; (C) Mechanism-agnostic — transcriptomics is not informative → UNCERTAIN.

Silencing gate: Target gene z < −2.0 → functionally absent → RESISTANT regardless of mechanism type.

T3  Pathway Agent

Modality: KEGG signalling pathway topology, bypass route detection.

Decision logic: (1) Find pathways containing the drug's target gene. (2) Apply pathway activity gate: skip pathways where <40% of member genes are expressed (z ≥ 0.5). (3) For active pathways, check for bypass routes whose genes are upregulated (z ≥ 1.0). (4) Bypass found + expressed → RESISTANT. (5) Target in pathway, no bypass → SENSITIVE. (6) Target not in any pathway → UNCERTAIN.

Self-attestation gate: Agent must answer 4 binary questions before committing to a RESISTANT verdict (bypass gene expressed, pathway active, mechanism relevant, bypass distinct from target). Score < 3/4 → verdict demoted to UNCERTAIN regardless of database result.

T4  Pharmacology Agent

Modality: Historical IC50 z-scores, drug target and mechanism data.

Decision logic: Anchors verdict directly to the pre-computed IC50 label (SENSITIVE/RESISTANT/UNCERTAIN). The IC50 label is a population-level prior derived from measured drug response; the agent reports it faithfully and notes that higher-tier molecular evidence (T1–T3) can override it.

Role in architecture: T4 is the most reliable signal for mechanism-agnostic drugs (chemotherapy, broad-spectrum kinase inhibitors) where genomic or pathway-level predictors are absent. It is the lowest priority in the axiom hierarchy for targeted therapies where mutation-level evidence exists.

All four agents run concurrently within the Orchestrator and produce independent EvidencePacks before any inter-agent communication occurs. This enforces the independence requirement of the debate protocol: an agent's R1 verdict must reflect its own evidence, not influenced by what other agents found. The structured reasoning protocol embedded in each agent's system prompt mandates step-by-step evidence integration before stating a verdict, reducing the probability of verdict-first, justification-second reasoning — a known failure mode of zero-shot LLM classification [4,16].

3.7 Evidence Pack Schema and Grounded Confidence Score

3.7.1 EvidencePack Schema

Each agent's output is a structured EvidencePack — a Pydantic-validated data class that constitutes the formal unit of inter-agent communication. The schema enforces type correctness and completeness: an agent cannot submit a partial or malformed evidence pack, which would otherwise propagate errors silently through the debate protocol.

FieldTypeDescription
agent_idstrUnique agent identifier (e.g. genomics_agent)
cell_linestrCCLE cell line name
drugstrDrug name as queried
verdictEnumSENSITIVE | RESISTANT | UNCERTAIN
confidencefloat [0,1]Grounded Confidence Score (GCS); see §3.7.2
evidence_tierEnumT1_STRUCTURAL | T2_TRANSCRIPTIONAL | T3_PATHWAY | T4_PHARMACOLOGICAL | T5_STATISTICAL
key_findingslist[Finding]Structured list of cited biomarkers with source, value, and interpretation
reasoningstrStep-by-step natural-language reasoning chain
caveatslist[str]Identified limitations or missing data
conflict_flagslist[str]Signals that contradict the stated verdict
peer_scoresdictPopulated in Round 2: scores given TO peers (key = label A/B/C)
self_attestationdict | NoneT3-only: 4-question binary checklist + integer score
data_statusstr | Nonedata_found | target_wild_type | signal_below_threshold | cell_line_missing

The key_findings list is particularly important for hallucination detection. Each Finding object contains a biomarker field (e.g. BRAF), a value field (e.g. V600E), and a data_source field. The hallucination rate is computed by checking whether the biomarker and value appear in the MCP tool responses logged for that agent's case — providing a quantitative, per-case measure of grounding fidelity.

3.7.2 Grounded Confidence Score (GCS)

The GCS replaces the LLM's self-reported confidence value, which has been shown to be poorly calibrated and inflated in zero-shot settings [4], with a formula-grounded score computed from four orthogonal components:

GCS = 0.40 · H + 0.30 · E + 0.20 · T + 0.10 · S

H (Hallucination score) = |{f ∈ key_findings : biomarker(f) ∈ MCP_response}| / |key_findings|
    (fraction of cited biomarkers whose name appears in the raw MCP tool response; 0.0 if no findings)

E (Evidence availability) = 1.0 if MCP returned any non-empty field, else 0.0

T (Tier weight): T1 = 1.0    T2 = 0.8    T3 = 0.6    T4 = 0.4    T5 = 0.2

S (Signal strength) = modality-specific scalar ∈ [0, 1]  (e.g. min(|z-score| / 3.0, 1.0) for pharmacology; clipped to [0, 1] for all tiers)
UNCERTAIN cap:  GCSfinal = min(GCS, 0.50)  if verdict = UNCERTAIN
Prevents an uncertain agent from receiving a confidence above 0.5, which would allow it to dominate the resolver despite not committing to a verdict.

The GCS formula is designed so that a high-confidence verdict requires both evidence availability (E = 1.0) and grounding (H close to 1.0), weighted by the biological priority of the modality (T) and the magnitude of the observed effect (S). An agent that cites biomarkers not present in its MCP responses receives H < 1.0, directly penalising hallucinated claims in the confidence score.

3.8 Debate Protocol

The debate protocol is modelled on clinical tumour board practice [5,6], adapted to the constraints of LLM agents. It comprises two rounds, with a resolver as a last resort. The design addresses the two primary failure modes of unstructured LLM debate: sycophantic convergence, in which agents revise their verdicts toward the majority position without new evidence [4]; and context overwhelm, in which a single agent is presented with all omics data simultaneously and fails to weight conflicting signals appropriately [17].

Figure 3. Debate protocol flow. Round 1 independent analysis feeds into a consensus check; if no consensus is reached, Round 2 peer critique fires, computing endorsement scores. If still no consensus, the AxiomResolver applies endorsement-primary, tier-secondary ordering to select the winning agent.

3.8.1 T3 Self-Attestation Gate

Before the T3 pathway agent's verdict is counted as decisive in the Round 1 consensus check, it must pass a self-attestation gate. The agent answers 4 binary questions about the quality of its own bypass evidence:

attestation_score = Σk=14 ak,  ak ∈ {0, 1}

Questions: (1) bypass gene is named and specific   (2) pathway is active in this cell line   (3) drug mechanism is relevant to this pathway   (4) bypass gene is distinct from the primary drug target

Gate: if attestation_score < 3 → T3 verdict demoted to UNCERTAIN for consensus purposes

3.8.2 Round 1: Independent Analysis and Consensus Check

In Round 1, all four agents run concurrently and independently. Each agent queries its MCP server(s), applies its modality-specific reasoning protocol, and produces an EvidencePack with a verdict (SENSITIVE, RESISTANT, or UNCERTAIN) and a GCS confidence score. Agents have no visibility into one another's findings during this round, enforcing the independence requirement.

After all four EvidencePacks are returned, the _check_consensus() function determines whether consensus can be established without escalating to Round 2:

  • Decisive threshold: An agent is decisive if its verdict is not UNCERTAIN. A single decisive agent is sufficient for R1 consensus (len(decisive) ≥ 1).
  • T3 self-attestation gate: The Pathway Agent's verdict is only counted as decisive if its self-attestation score ≥ 3/4. A low-quality bypass claim (score < 3) is demoted to UNCERTAIN for the purpose of the consensus check, preventing the pathway agent from winning cases it cannot substantiate.
  • T1 veto: If a T1 genomics agent has a decisive verdict that contradicts the majority verdict of all other decisive agents, consensus fails and the case escalates to Round 2. This prevents a clear genomic signal from being overridden by a pharmacological majority without debate.
  • Majority requirement: If multiple decisive agents are present, the majority verdict must hold strictly (n > len(decisive) / 2). A 1-vs-1 split between SENSITIVE and RESISTANT decisive agents fails the majority check and escalates to Round 2.

3.8.3 Round 2: Peer Critique

If R1 consensus is not reached, the DebateEngine invokes the peer critique round. In Round 2, each agent reviews the EvidencePacks of all three peers and scores their reasoning quality using a tier-specific binary checklist. Critically, verdicts are locked: agents cannot change their SENSITIVE/RESISTANT/UNCERTAIN decision in Round 2. Only confidence can be adjusted (by ±0.10) based on what peers found. This design prevents sycophantic convergence: agents cannot capitulate to social pressure, only update confidence based on the factual quality of peer reasoning.

The tier-specific checklists are designed to test the factual grounding of each peer's claims, not their biological plausibility:

TierChecklist Questions (4 per tier, binary)
T1 1. Named a specific mutation or CNV in the target gene?   2. Cited a CIViC entry linking variant to drug?   3. Confirmed variant is somatic?   4. Functional direction supports verdict?
T2 1. Reported a specific numeric z-score?   2. Expression level consistent with verdict direction?   3. Accounted for drug mechanism type (mutation-driven vs expression-driven)?   4. Named at least one gene with its z-score?
T3 1. Named at least one specific bypass gene?   2. Reported pathway activity score or fraction expressed?   3. Bypass gene mechanistically connects to resistance?   4. Bypass gene distinct from primary target?
T4 1. Reported specific IC50 z-score value?   2. Stated the pre-computed IC50 label?   3. IC50 label supports verdict?   4. Acknowledged T4 can be overridden by T1–T3?

Each checklist answer is binary. The peer score and endorsement total are computed as:

peer_score(agentj → agenti) = Σk=14 ck / 4,  ck ∈ {0, 1}

endorsement(agenti) = Σj ≠ i peer_score(agentj → agenti)

Range of endorsement: [0.0, 3.0] for a 4-agent system

Confidence adjustment: new_conf = clip( old_conf ± δ, 0.0, 1.0 ),  |δ| ≤ 0.10
UNCERTAIN cap still applies: new_conf = min(new_conf, 0.50) if verdict = UNCERTAIN

3.9 Axiom Hierarchy and Conflict Resolution

The axiom hierarchy encodes the causal ordering of biological evidence types into the conflict resolution mechanism. The hierarchy is grounded in established principles of molecular biology and clinical oncology: DNA-level structural alterations are the highest-fidelity determinants of drug-target interaction state, because they directly alter the physical binding site or gene expression capacity of the drug target [5,7]. mRNA expression provides a functional-state signal but is subject to post-transcriptional regulation. Pathway topology provides mechanistic context but requires inferred connections. Pharmacological history is a population-level prior that integrates all upstream molecular factors but lacks specificity for the individual cell line's molecular state.

Figure 4. The five-tier axiom hierarchy. Tiers reflect the causal proximity of the evidence type to the drug-target interaction state. T1 structural evidence (mutations directly altering the drug-binding site) holds the highest axiom weight and GCS tier weight.

3.9.1 Resolver Algorithm

If neither R1 nor R2 consensus is reached, the AxiomResolver selects the winning agent using a three-key lexicographic sort:

winner = argmaxp ∈ candidates ( endorsement(p),  axiom_weight(tier(p)),  GCS(p) )

where axiom_weight is: T1_STRUCTURAL = 5    T2_TRANSCRIPTIONAL = 4    T3_PATHWAY = 3    T4_PHARMACOLOGICAL = 2    T5_STATISTICAL = 1

candidates = decisive agents (verdict ≠ UNCERTAIN) if any exist,
           else all agents (fallback when all UNCERTAIN)

The sort is lexicographic: endorsement is compared first; axiom tier breaks ties; GCS breaks further ties. This means a T4 agent with very high peer endorsement can override a T1 agent with low endorsement, which is the intended behaviour — factual grounding as judged by peers outweighs nominal tier priority.

Weak T1 Override Gate

A special case applies when T1 evidence is present but weakly supported:

Confidence-weighted fallback is used when ALL of the following hold:

(1) ∃ p* with tier(p*) = T1 and p* is decisive (verdict ≠ UNCERTAIN)
(2) GCS(p*) < τ  (τ = 0.70, T1_OVERRIDE_CONFIDENCE_THRESHOLD)
(3) All lower-tier decisive agents unanimously agree:   |{verdict(p) : tier(p) ≠ T1, decisive(p)}| = 1 and that verdict ≠ verdict(p*)

Fallback:  winning_verdict = argmaxv Σ{p : verdict(p) = v} GCS(p)

Confidence Decay and Final Confidence

For each agent i after resolver selects winner w:

adjusted_conf(agenti) =  GCS(agenti)                     if verdict(agenti) = verdict(w)
 GCS(agenti) × (1 − δ)    if verdict(agenti) ≠ verdict(w)

δ = 0.15  (CONFIDENCE_DECAY_PER_FLIP)

final_confidence (RESOLVER_TIEBREAK) = mean({ adjusted_conf(p) : p ∈ all agents })

final_confidence (CONSENSUS_R1 or R2) = mean({ GCS(p) : verdict(p) = consensus_verdict })

3.10 Evaluation Design and Metrics

3.10.1 Primary Metrics

The framework is evaluated using four complementary metrics that capture different aspects of predictive performance:

MetricFormulaRationale
AUROCArea under the ROC curve (confidence scores vs binary SENSITIVE/RESISTANT labels)Measures ranking quality; threshold-independent; standard pharmacogenomics benchmark
AUPRCArea under the precision-recall curveMore informative than AUROC under class imbalance; penalises false positives in the SENSITIVE class
Cohen's κ(P_observed − P_chance) / (1 − P_chance)Measures label agreement beyond chance; penalises confidently wrong predictions; scale-invariant
Spearman ρRank correlation between predicted confidence and ground truth z-scoreAssesses whether the framework's confidence is monotonically aligned with effect size

UNCERTAIN predictions are excluded from AUROC/AUPRC/Spearman computation; they are included in Cohen's κ as a third label class. Coverage is defined as:

coverage = ndecisive / ntotal

where ndecisive = cases where final_verdict ≠ UNCERTAIN AND ground_truth ≠ UNCERTAIN

Sensitivity Score for Ranking Metrics

AUROC and AUPRC require a continuous score. The sensitivity score maps the framework's output to a scalar where higher values indicate more SENSITIVE predictions:

sensitivity_score(r) =  final_confidence(r)            if final_verdict(r) = SENSITIVE
 1 − final_confidence(r)    if final_verdict(r) = RESISTANT

Labels for AUROC: y = 1 if ground_truth = SENSITIVE, y = 0 if ground_truth = RESISTANT
AUROC = P(score(SENSITIVE case) > score(RESISTANT case))

3.11 Ablation Study Design

Seven ablation conditions are evaluated to isolate the contribution of individual architectural components. Each ablation removes or modifies exactly one component of the full system while keeping all others constant, enabling attribution of performance differences to specific design decisions.

ConditionModificationTests
full_systemNo modification (baseline)Combined contribution of all components
no_debateReplace DebateEngine with majority-vote aggregator; no Round 2 critiqueWhether the two-round debate protocol adds value over simple majority vote
no_axiomsReplace AxiomResolver with confidence-only resolver (highest GCS wins)Whether the axiom hierarchy adds value over pure confidence ordering
no_genomicsRemove T1 genomics agent; 3-agent debateContribution of structural mutation evidence
no_transcriptomicsRemove T2 transcriptomics agent; 3-agent debateContribution of mRNA expression evidence
no_pathwayRemove T3 pathway agent; 3-agent debateContribution of pathway topology evidence
no_pharmacologyRemove T4 pharmacology agent; 3-agent debateContribution of IC50 pharmacological prior
single_agent_multiomicsReplace 4-agent debate with single agent reading all MCP sourcesWhether debate adds value over a single agent with equal data access

The single_agent_multiomics condition is particularly important for the thesis claim. It tests whether the debate mechanism adds value beyond providing a well-contextualised prompt: if a single agent reading all four data sources matches or exceeds the performance of the four-agent debate, then the architectural complexity of the debate protocol is not justified by its predictive contribution. Conversely, if the debate system exceeds the single-agent baseline, it demonstrates that the structured multi-round protocol — independent analysis, peer critique, and axiom-governed resolution — extracts more information from the same data than a single synthesising agent.

3.12 Baseline Comparators

The framework is compared against two baseline systems that represent the current state of the field:

Monolithic LLM Baseline

A single LLM agent receives the same prompt structure as the specialist agents but is provided with all four modality datasets simultaneously in a single context window. This baseline tests whether the multi-agent architecture adds value over single-model multi-omics reasoning, and directly probes the context-overwhelm failure mode described in the literature [17]. The monolithic agent uses the same LLM backend (Gemini 3.1 Flash Lite) and the same GCS confidence scoring to ensure fair comparison.

Random Forest Baseline

A Random Forest classifier is trained on GDSC2 features: binary mutation presence/absence vectors per cancer gene census gene, expression z-scores for the drug's target genes, and the pre-computed IC50 z-score. Training uses 5-fold cross-validation on the development set. This baseline establishes the performance achievable by a classical machine learning model with equivalent feature access, providing an accuracy anchor point against which the LLM framework's interpretability and reasoning quality can be assessed. A performance improvement over Random Forest demonstrates that the LLM agents add value beyond feature lookup; a decrease provides evidence that the structured reasoning protocol introduces unnecessary errors on cases well-handled by tabular classification.
