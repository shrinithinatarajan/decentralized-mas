A — No R2 consensus check: all non-R1 cases forced into resolver

src/protocols/debate_engine.py · run() method · line ~130
PLAUSIBLE
What the code does

After _run_critique_round() completes, run() immediately calls self._resolver.resolve(). There is no second call to _check_consensus() on the updated packs. Every case that doesn’t reach R1 consensus exits with forced=True and resolution_method="RESOLVER_TIEBREAK" regardless of whether peer critique brought agents to agreement.

Failure scenario
R1: T4=SENSITIVE(0.82), T1=UNCERTAIN, T2=UNCERTAIN, T3=UNCERTAIN → no majority → R2.
R2 peer critique: T1 and T2 update to SENSITIVE based on T4’s evidence. Now 3 agents agree.
Expected: CONSENSUS_R2. Actual: resolver fires anyway, T4 wins by axiom weight, forced=True.
Effect: resolver rate is artificially inflated; confidence is computed over all agents (see Bug D) instead of just agreeing ones.
The intended flow (from run() docstring)
1. R1 check  → done if consensus
2. R2 critique
3. R2 check  → done if consensus   ← THIS STEP IS MISSING
4. Resolver  → forced=True
Fix
After packs = critiqued, add one consensus check before the resolver: 
# After Round 2 critique
packs = critiqued

# R2 consensus check  ← ADD THIS BLOCK
consensus_verdict = _check_consensus(packs)
if consensus_verdict is not None:
    result = self._build_result(
        packs, consensus_verdict, cell_line, drug,
        rounds_taken=2, forced=False,
        resolution_method="CONSENSUS_R2", trace=trace,
    )
    if run_logger:
        run_logger.log_resolution(
            case_id=case_id, resolution_method="CONSENSUS_R2",
            winning_agent=result.winning_agent,
            verdict=result.final_verdict.value, forced=False,
        )
    return result

# Resolver tiebreak (last resort)
resolution = self._resolver.resolve(packs, peer_endorsements=peer_endorsements)

E — T3 is silently always demoted when LLM omits self_attestation

src/agents/base_agent.py · _parse_pack()  +  src/protocols/debate_engine.py · _check_consensus()
CONFIRMED
What the code does

_parse_pack() only sets pack.self_attestation if the key "self_attestation" is present in the LLM’s JSON response. If the LLM (especially smaller models like Gemini Flash Lite) omits the field, self_attestation stays None. Then in _check_consensus():

score = (p.self_attestation or {}).get("score", 0)
if score < 3:
    continue  # T3 demoted

None or {} = {} → {}.get("score", 0) = 0 → 0 < 3 → T3 always demoted. There is no distinction between “T3 self-assessed as weak” and “T3 forgot to include the field.” In production traces, T3 pathway evidence is entirely absent from consensus decisions even when the pathway evidence is strong, because Gemini Flash Lite frequently returns JSON without the extra field.

Failure scenario
Cell line with a known KRAS bypass gene (CRAF overexpressed). T3 correctly votes RESISTANT with bypass evidence but omits self_attestation from its JSON. Score defaults to 0. T3 is dropped from decisive pool. Resolver picks T4 (SENSITIVE from IC50 prior). Wrong answer, no indication in trace that T3 was silently excluded.
Fix
Two-part fix: (1) Add fallback self-attestation scoring from individual boolean fields; (2) demote only if explicitly scored low, not when missing. 
# In base_agent.py _parse_pack(), after parsing:
if "self_attestation" in data:
    pack.self_attestation = data["self_attestation"]
elif pack.evidence_tier.value == "T3_PATHWAY":
    # Reconstruct score from individual boolean fields if present
    sa = {
        k: data.get(k)
        for k in ("bypass_gene_expressed", "pathway_active", "mechanism_relevant", "bypass_distinct")
    }
    if any(v is not None for v in sa.values()):
        score = sum(1 for v in sa.values() if v is True)
        pack.self_attestation = {**sa, "score": score}
    # else: leave None — _check_consensus will treat as unscored (see below)

# In debate_engine.py _check_consensus(), change the gate:
if p.evidence_tier == EvidenceTier.T3_PATHWAY:
    sa = p.self_attestation or {}
    score = sa.get("score")
    if score is None:
        pass  # field absent: do NOT demote — treat as unscored, let it through
    elif score < 3:
        continue  # explicitly failed self-attestation
    filtered.append(p)
continue  # skip the append below
filtered.append(p)

D — Resolver final_confidence averaged over all agents, including UNCERTAIN ones

src/protocols/debate_engine.py · run() · avg_conf computation
CONFIRMED
What the code does
# Resolver path (debate_engine.py)
avg_conf = sum(p.confidence for p in resolution.adjusted_packs) / len(resolution.adjusted_packs)

# Consensus path (_build_result)
agreeing = [p for p in packs if p.verdict == verdict]
avg_conf = sum(p.confidence for p in agreeing) / len(agreeing)  # only agreeing agents

These two paths are inconsistent. In the resolver path, all 4 agents are included. UNCERTAIN agents are capped at 0.5. After confidence decay (15% for non-winners), a typical resolver case with 1 decisive winner at 0.85 and 3 UNCERTAIN agents at 0.40 each yields: (0.85 + 0.40 + 0.34 + 0.34) / 4 = 0.48 — less than 0.5, which would rank below any UNCERTAIN consensus verdict in an AUROC sort. This depresses the AUROC for resolver cases specifically.

Fix
Use only the winning agent’s confidence for resolver path, consistent with what the resolver actually decided.
# Replace avg_conf computation in resolver path:
winner_pack = next(p for p in resolution.adjusted_packs if p.agent_id == resolution.winning_agent)
final_conf = winner_pack.confidence
# Or to match consensus path logic: mean of agents who agree with winning verdict
agreeing = [p for p in resolution.adjusted_packs if p.verdict == resolution.verdict]
final_conf = sum(p.confidence for p in agreeing) / len(agreeing)

CONFIRMED
The discrepancy
# Docstring:

# Actual code:
counts = Counter(p.verdict for p in decisive)

Under the code: T4 wins R1 with forced=False, resolution_method=CONSENSUS_R1. No peer review happens. For CTRPv2 test cases, T4 is very often the sole decisive agent (T1/T2/T3 lack data), so this path fires constantly.

if not decisive or len(decisive) < 2:   # ← add minimum

Option 2 (make docstring match code): If single-agent R1 wins are acceptable, update the docstring and accept the behaviour — but note it bypasses all peer review for sole-decisive cases.
If you enforce min-2
More cases go to R2 → peer checklists run more → more robust verdicts, but higher API cost.
If you keep current
T4 frequently wins unreviewed. Fixes need to come from GCS calibration and confidence decay instead.

H — winning_agent in consensus path selected by confidence, not axiom tier

src/protocols/debate_engine.py · _build_result()
CONFIRMED
What the code does
winning = max(agreeing, key=lambda p: p.confidence).agent_id

In the resolver path, winning_agent comes from AxiomResolver which correctly ranks by (endorsement, axiom_weight, confidence). In the consensus path, it’s purely max(confidence). So T4 at 0.83 is reported as winning over T1 at 0.79 even when T1’s BRAF V600E finding is why the case was SENSITIVE. This makes the winning_agent field in traces misleading for consensus cases and creates an inconsistent definition across resolution methods.

Fix
Apply the same sort key as the resolver in _build_result.
from src.schemas.axiom_rules import AXIOM_HIERARCHY, EVIDENCE_TO_AXIOM_TIER

winning = max(
    agreeing,
    key=lambda p: (
        AXIOM_HIERARCHY[EVIDENCE_TO_AXIOM_TIER[p.evidence_tier]],
        p.confidence,
    )
).agent_id

B/F — Passthrough agent grants maximum endorsement (3.0 default) to all its peers

src/protocols/debate_engine.py · _run_critique_round() · endorsements aggregation
PLAUSIBLE
What the code does
# In _run_critique_round:
for agent_id, agent in agent_map.items():  # agent_map = {a.agent_id: a for a in agents}
    if agent is None:  # agent not found
        async def _passthrough(p=pack): return p   # returns original pack, no peer_scores
        tasks.append(_passthrough())

# Endorsement aggregation:
for reviewer in critiqued:
    peers = peer_order[reviewer.agent_id]
    for i, peer_pack in enumerate(peers):
        label = chr(ord('A') + i)
        endorsements[peer_pack.agent_id] += reviewer.peer_scores.get(label, 3.0)  # ← 3.0 default

When an agent is missing from agent_map (e.g. an ablation run with agents removed, or an agent that raised an exception), its pack passes through unchanged with an empty peer_scores = {}. The endorsement loop then adds 3.0 for every peer it should have reviewed — the maximum possible endorsement value (3 peers × 1.0 each = 3.0 total). This would corrupt resolver tiebreaks in any ablation condition that removes an agent.

Fix
Change the default to 0.0 so a non-participant contributes nothing to endorsements.
endorsements[peer_pack.agent_id] += reviewer.peer_scores.get(label, 0.0)  # was 3.0

G — json.loads(result.data) fails if fastmcp returns pre-parsed object

src/agents/base_agent.py · _call_tool()
PLAUSIBLE
What the code does
async def _call_tool(self, tool: str, args: dict):
    async with Client(self.mcp_app) as client:
        result = await client.call_tool(tool, args)
    data = json.loads(result.data)   # ← TypeError if result.data is already dict/list

Depending on fastmcp version and how the MCP server serialises its return, result.data may be a pre-parsed Python object rather than a JSON string. json.loads() on a dict raises TypeError, which would propagate up through _fetch_evidence and cause the agent to produce a parse-failed UNCERTAIN pack. No data, no agent contribution, no error message to the user.

Fix
Guard against already-parsed data.
data = result.data if isinstance(result.data, (dict, list)) else json.loads(result.data)

I — No confidence penalty when only one agent is decisive (singleton overconfidence)

src/agents/gcs.py · compute_gcs()  /  src/agents/base_agent.py · analyze()
PLAUSIBLE
What the code does

GCS is computed independently per agent from its own retrieval quality. When only one agent is decisive and the other three are UNCERTAIN, the sole agent’s GCS can be 0.85+ (T4 with a clean IC50 hit). This is reported as final_confidence with no discount for the fact that there is zero cross-modal corroboration. The error analysis in the thesis identified HuP-T4+Crizotinib and A375+Tanespimycin as wrong predictions where T4 was the sole decisive agent at high confidence.

Failure scenario
T4 IC50 z = −0.62 → GCS ≈ 0.71 → SENSITIVE at 0.71 confidence.
T1/T2/T3 all UNCERTAIN (no data). No peers reviewed T4’s claim.
sensitivity_score = 0.71 → contributes strongly to AUROC ranking.
Ground truth: RESISTANT. High-confidence wrong answer that AUROC penalises heavily.
Fix
Apply a singleton penalty in _build_result and the resolver path: if only one agent is decisive, multiply final_confidence by 0.85.
# In _build_result:
n_decisive = len([p for p in packs if p.verdict != Verdict.UNCERTAIN])
if n_decisive == 1:
    avg_conf *= 0.85  # singleton penalty — no cross-modal corroboration

# Similarly in resolver path after computing final_conf:
n_decisive = len([p for p in packs if p.verdict != Verdict.UNCERTAIN])
if n_decisive == 1:
    final_conf *= 0.85
