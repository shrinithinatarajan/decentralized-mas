Introduction

Multi-omics,

By

To  translate  this  massive,  high-dimensional  volume  of  multi-omic  data  into  actionable  treatment

MDTs

Yet,

This  study  positions  itself  at  the  intersection  of  precision  oncology  and  artificial  intelligence  by  
computationally
 
modeling
 
the
 
MDT
 
workflow.
 
Currently,
 
most
 
AI
 
applications
 
in
 
this
 
space
 
rely
 
on
 
monolithic
 
Large
 
Language
 
Models
 
(LLMs).
 
However,
 
when
 
forced
 
to
 
synthesize
 
massive,
 
conflicting
 
multi-omics
 
payloads
 
(e.g.,
 
genomics
 
versus
 
proteomics),
 
single
 
LLMs
 
suffer
 
from
 
Context
 
Overwhelm,
 
frequently
 
ignoring
 
critical
 
pathway
 
bypass
 
mechanisms
 
and
 
outputting
 
highly
 
confident
 
but
 
biologically
 
inaccurate
 
drug
 
response
 
predictions.
 
To  resolve  this,  this  research  introduces  a  Decentralized  Multi-Agent  System  (MAS)  that  acts  as  
a
 
council
 
of
 
cooperating

By

(A2A)

emulates

rigorous,
 
peer-reviewed
 
environment
 
of
 
a
 
human
 
tumor
 
board.
 
Ultimately,
 
this
 
approach
 
aims
 
to
 
bridge
 
the
 
gap
 
between
 
complex
 
multi-omic
 
data
 
and
 
safe,
 
auditable,
 
and
 
highly
 
personalized
 
clinical
 
decision-making.

Brief  Methodology  
This  research  implements  a  decentralized,  multi-agent  AI  architecture  for  precision  oncology,  
utilizing
 
the
 
Model
 
Context
 
Protocol
 
(MCP)
 
to
 
interface
 
with
 
four
 
distinct
 
biological
 
data
 
modalities.
 
The
 
study
 
transitions
 
from
 
traditional
 
text-based
 
retrieval
 
to
 
a
 
federated
 
API
 
approach,
 
where
 
reasoning
 
is
 
grounded
 
in
 
live,
 
structured
 
datasets.
 
Phase  1:  Input  Orchestration  (The  Triage  Agent)  
The  system  employs  a  Triage  Agent  as  a  pre-processor  to  convert  natural  language  queries  
into
 
a
 
machine-readable
 
JSON
 
input.
 
●  Entity  Extraction:  The  agent  extracts  the  subject_id  (e.g.,  COLO205)  and  target_drug  
(e.g.,
 
Vemurafenib).
 ●  Route  Determination:  Based  on  these  parameters,  the  Triage  Agent  selects  the  
appropriate
 
API
 
endpoints
 
for
 
the
 
subsequent
 
Council
 
debate,
 
mapping
 
common
 
cell
 
line
 
names
 
to
 
standardized
 
Sanger
 
Model
 
IDs
 
or
 
COSMIC
 
IDs
.
 
Phase  2:  Agent-Specific  Data  Acquisition  (The  API  Layer)  
Four  specialized  agents  operate  as  independent  MCP  clients,  querying  the  following  first-party  
and
 
production-grade
 
APIs:
 
1.  Genomics  Agent:  ○  Interface:  cBioPortal  MCP  Server .  ○  API  Target:  https://www.cbioportal.org/api.  ○  Primary  Tool:  get_mutations for  fetching  non-synonymous  DNA  variants  and  get_copy_number_alterations to  identify  oncogenic  amplifications  (e.g.,  EGFR).  2.  Expression  Agent:  ○  Interface:  BioThings  CCLE  API .  ○  API  Target:  https://biothings.ncats.io/ccle.  ○  Primary  Tool:  /query endpoint  to  retrieve  z-scored  RNA-Seq  and  Proteomic  
expression
 
data
 
for
 
the
 
specific
 subject_id.  3.  Pathways  Agent  :  ○  Interface:  KEGG  REST  API .  ○  API  Target:  http://rest.kegg.jp/get/{pathway_id}/kgml.  ○  Primary  Tool:  Fetches  KGML  (XML)  network  files.  A  local  Python-based  parser  
(using
 xml.etree)  converts  the  XML  into  a  directional  graph  (edges/nodes)  for  
LLM
 
consumption,
 
identifying
 
downstream
 
bypass
 
mechanisms.
 4.  Pharmacology  Agent:  ○  Interface:  Sanger  DepMap  /  Cell  Model  Passports  API .  ○  API  Target:  https://api.cellmodelpassports.sanger.ac.uk.  ○  Primary  Tool:  /models/{id}/datasets/gdsc to  retrieve  historical  LN_IC50  values  
and
 
drug
 
sensitivity
 
highlights.
 
Phase  3:  The  Agent-to-Agent  (A2A)  Debate  Protocol  
The  agents  enter  a  multi-round  deliberation  cycle  via  a  Structured  JSON  Message  Bus .  
●  Domain  Isolation:  Each  agent  only  "sees"  the  API  data  from  its  specific  domain  until  the  
debate
 
begins.
 ●  Logical  Synthesis:  Agents  must  justify  their  prediction  (Sensitive  or  Resistant)  by  citing  
specific
 
data
 
points
 
retrieved
 
from
 
their
 
respective
 
APIs.
 
Phase  4:  Evaluation  and  Validation  
●  Quantitative  Benchmark:  System  accuracy  is  measured  against  a  hold-out  set  of  
known
 
GDSC
 
outcomes
 
using
 
Precision
 
and
 
Recall.
 ●  Qualitative  Analysis:  The  "Agent  Debate  Trace"  is  evaluated  for  biological  accuracy,  
ensuring
 
the
 
reasoning
 
follows
 
established
 
molecular
 
biology
 
signaling
 
cascades
 
(e.g.,
 
verifying
 
that
 
a
 
BRAF
 
block
 
is
 
correctly
 
identified
 
as
 
failing
 
due
 
to
 
an
 
EGFR
 
bypass).
 
This  methodology  establishes  a  rigorous  framework  for  an  Explainable  AI  (XAI)  system  that  
moves
 
beyond
 
simple
 
text
 
generation
 
into
 
factual,
 
data-driven
 
oncological
 
reasoning.
 
Validation  
To  ensure  the  integrity  of  the  validation  process  and  avoid  data  leakage,  the  Pharmacology  
Agent
 
will
 
utilize
 
the
 
GDSC2
 
dataset
 
for
 
historical
 
IC50
 
baselining,
 
while
