Project at a Glance

The problem: Given a cancer cell line and a drug, predict whether the cell line will be SENSITIVE, RESISTANT, or UNCERTAIN to that drug — using only molecular evidence retrieved from structured databases, no supervised training.

  • Zero-shot: no fine-tuning, no labelled training data, no embeddings
  • MCP-grounded: each agent queries a dedicated structured database via FastMCP before reasoning — this is the anti-hallucination layer
  • Debate-driven: unanimity consensus means any single dissenting agent triggers a full debate round; 45.2% of cases enter debate
  • Interpretable: every verdict comes with a full reasoning chain, cited evidence, and a winning agent + axiom
  • Zero false negatives: the system never misclassifies a resistant case as sensitive (FN=0, NPV=1.0)

Ground Truth Labels

The gold standard evaluation set uses 31 literature-validated cases with labels independent of GDSC/CTRP assay z-scores. This avoids the leakage problem where T4 pharmacology agent queries the same database that generated the labels.

IC50 Z-Score (drug-normalised) — used for CTRP labels only
z = (ln IC50 − μdrug) / σdrug
z < −0.5 → SENSITIVE
−0.5 ≤ z ≤ +0.5 → UNCERTAIN
z > +0.5 → RESISTANT
Label leakage warning: Do NOT evaluate on CTRP-labelled test sets when T4 queries CTRPv2/GDSC2 IC50 data — the pharmacology agent essentially has the answer. All final results use the gold standard set with clinical/literature labels.

The Four Agents

T1 — Genomics Agent (axiom priority: 5)

  • Queries CCLE mutations + CNV for somatic alterations in the drug's target genes
  • CIViC drug-specific match: checks civic_description for THIS drug name; same mutation can sensitise to drug A and resist drug B
  • OncoKB: Gain-of-function + inhibitor drug → SENSITIVE; Loss-of-function → RESISTANT/UNCERTAIN
  • DepMap Chronos supplement: ≤ −1.0 strong essential; −0.5 to −1.0 weak signal (conf cap 0.55); > −0.5 non-informative
  • RPPA protein expression: if target WT, RPPA > 0.5 → SENSITIVE (cap 0.65)
  • OpenTargets fallback: phase ≥ 3 = strong; phase 1–2 = weak
  • T1_OVERRIDE threshold: if T1 confidence < 0.80 AND lower tiers unanimously disagree → resolver uses confidence-weighted vote instead of T1 tier-priority

T2 — Transcriptomics Agent (axiom priority: 4)

  • Queries CCLE mRNA z-scores for the drug's target gene(s)
  • Drug mechanism classification: mutation-driven vs expression-driven
  • Expression-driven: z > 1.5 → SENSITIVE (conf 0.75–0.85); z 1.0–1.5 → SENSITIVE (conf 0.55–0.70)
  • Silencing gate: z < −2.0 → target absent → RESISTANT
  • Round 1 only: T2 does NOT check bypass genes in R1; bypass detection belongs to T3. In R2, after seeing T3's evidence, T2 can check bypass gene expression to revise verdict
  • Known issue: T2 sometimes states mutation facts (e.g. “NCI-H1975 is EGFR L858R/T790M”) from LLM training data rather than CCLE tools — cross-tier leakage (15.7% of decisive T2 calls)

T3 — Pathway Agent (axiom priority: 3)

  • Queries KEGG for pathway membership and bypass gene expression (pre-fetched from T2 MCP)
  • Pathway activity = fraction of pathway member genes with z ≥ 0.5; threshold = 0.25 (25%)
  • Bypass filter: only activating relationship genes counted; inhibition-relationship genes excluded
  • Cancer-type-specific pathways (hsa05210–hsa05226) skipped for bypass unless tumor type matches
  • Self-attestation 4-boolean gate: score ≥ 3 → RESISTANT (hard constraint)
  • T3 quality gate in consensus/resolver: RESISTANT only counts if score ≥ 3; SENSITIVE only counts if pathway_active = True

T4 — Pharmacology Agent (axiom priority: 2)

  • Queries CTRPv2/GDSC2 for historical IC50 z-score for this exact (cell line, drug) pair
  • z < −0.5 → SENSITIVE; z > +0.5 → RESISTANT; |z| ≤ 0.5 → UNCERTAIN
  • Non-targeted drugs: T1 structural mutation evidence is demoted; T4 IC50 wins tiebreaks
  • Lowest axiom priority: empirical IC50 prior can be overridden by molecular evidence
  • Known issue: T4 sometimes states cell-line phenotypes (p53-null, ER-positive) from training data rather than retrieved data

T3 Pathway Agent — Deep Dive Updated

Self-Attestation System (4 booleans)

T3 is the most failure-prone agent because KEGG doesn't encode pharmacokinetics or paradoxical feedback. To prevent low-quality T3 verdicts from swaying consensus, a self-attestation gate is enforced both in the LLM prompt and in the Python consensus/resolver logic.

# T3 self-attestation fields (added to JSON response alongside EvidencePack)
{
  "bypass_gene_expressed": bool,   # found ≥1 bypass gene at z≥1.0 in this cell line?
  "pathway_active": bool,          # ≥25% of pathway member genes expressed at z≥0.5?
  "mechanism_relevant": bool,      # does bypass gene mechanistically connect to resistance?
  "bypass_distinct": bool,         # bypass gene ≠ primary drug target gene?
  "score": int                     # sum of True values; range 0–4
}

Verdict Rules (Hard Constraints)

These are protocol constraints, not guidelines. The LLM is instructed that any other verdict is a protocol violation.
T3 verdict decision tree. Score ≥ 3 is the only path to RESISTANT — no exceptions.

Pathway Activity Threshold: Why 0.25?

The threshold was lowered from 0.40 to 0.25 after measuring actual pathway activity scores across the 31 gold standard cases.

  • KEGG pathways contain 80–300 genes. At a 40% threshold, almost all pathway activity scores (which ranged 0.19–0.35 in practice) fell below the gate, making pathway_active always False
  • 25% = a quarter of pathway genes expressed at z ≥ 0.5 is a reasonable biological signal that a pathway is active in a given cell line
  • T3's _compute_signal is capped at 0.25 from pathway activity alone (bypass confirmed = 1.0)
# src/agents/pathway_agent.py — pathway activity gate
if activity_score < 0.25:   # skip pathways with < 25% genes expressed
    continue

# _compute_signal: caps pathway-only signal at 0.25
def _compute_signal(self, evidence: dict) -> float:
    confirmed_bypasses = evidence.get("confirmed_bypass_genes", [])
    if confirmed_bypasses:
        return 1.0   # bypass confirmed expressed → strong RESISTANT signal
    activity_scores = evidence.get("pathway_activity_scores", {})
    max_activity = max(activity_scores.values()) if activity_scores else 0.0
    return min(max_activity, 0.25)  # at most 0.25 from pathway activity alone

Bypass Gene Filtering

Not all bypass genes in KEGG confer resistance. The agent applies three filters before counting a bypass:

  1. Relationship filter: only relationship="activation" (or null/unknown) genes count; inhibition-relationship genes are suppressed by the blocked pathway and cannot rescue the cell
  2. Expression filter: bypass gene must be expressed in this cell line at z ≥ 1.0 (queried from T2 MCP pre-fetch)
  3. Cancer-type filter: cancer-type-specific KEGG pathways (hsa05210–hsa05226) are skipped for bypass unless the tumor type matches the cell line context

T3 Quality Gate (Consensus + Resolver)

Both _check_consensus() and AxiomResolver apply the same gate before counting T3 as a decisive agent:

def _t3_passes(p: EvidencePack) -> bool:
    if p.evidence_tier != EvidenceTier.T3_PATHWAY:
        return True
    sa = p.self_attestation or {}
    if p.verdict == Verdict.RESISTANT:
        return (sa.get("score") or 0) >= 3   # must have strong self-attestation
    if p.verdict == Verdict.SENSITIVE:
        return bool(sa.get("pathway_active", False))  # pathway must be active
    return True  # UNCERTAIN always passes

This means a T3 pack with score=2 voting RESISTANT is treated as if T3 was UNCERTAIN for consensus and resolver purposes — it cannot pull the system to a wrong verdict on weak evidence.

EvidencePack Schema

Each agent returns one EvidencePack (Pydantic model). This is the unit of information flowing through the debate. New raw_evidence field added for faithfulness evaluation.

class EvidencePack(BaseModel):
    agent_id:         str           # e.g. "genomics_agent"
    cell_line:        str           # e.g. "NCI-H1975"
    drug:             str           # e.g. "Osimertinib"
    verdict:          Verdict       # SENSITIVE | RESISTANT | UNCERTAIN
    confidence:       float         # GCS score [0.0, 1.0]; UNCERTAIN capped at 0.50
    evidence_tier:    EvidenceTier  # T1_STRUCTURAL ... T4_PHARMACOLOGICAL
    key_findings:     list[Finding] # [{biomarker, value, interpretation, data_source}]
    reasoning:        str           # full LLM reasoning chain
    caveats:          list[str]
    conflict_flags:   list[str]
    peer_scores:      dict          # {"A": 0.75, "B": 1.0} filled after Round 2
    data_status:      str | None    # "data_found"|"target_wild_type"|"signal_below_threshold"...
    self_attestation: dict | None   # T3 only: {bypass_gene_expressed, pathway_active, ..., score}
    raw_evidence:     dict | None   # NEW: full MCP tool output for faithfulness evaluation

The raw_evidence dict is the unprocessed output of _fetch_evidence(). For T1 it contains {mutations, cnv, rppa_expression}; for T2 {target_expression, high_expression_context}; for T3 {pathway_membership, bypass_check, pathway_activity_scores, confirmed_bypass_genes}; for T4 {ic50, drug_info}. This enables the LLM judge to verify that every factual claim in reasoning is traceable to actual retrieved data.

GCS Formula (Grounded Confidence Score)

The GCS replaces the LLM's raw self-reported confidence with a structured score computed from the evidence. It is calculated after the LLM returns its pack, overwriting the LLM's stated confidence value.

Grounded Confidence Score
GCS = (H × 0.40) + (E × 0.30) + (T × 0.20) + (S × 0.10)

H (Hit rate, weight 0.40) = fraction of cited biomarkers found in raw MCP evidence
  = count(key_findings where biomarker appears in evidence dict) / len(key_findings)
  If no key_findings → H = 0.0

E (Evidence completeness, weight 0.30) = 1.0 if MCP returned any non-empty data, else 0.0

T (Tier weight, weight 0.20): T1=1.0, T2=0.8, T3=0.6, T4=0.4, T5=0.2

S (Signal strength, weight 0.10) = LLM's raw self-reported confidence, clamped to [0, 1]

UNCERTAIN cap: if verdict = UNCERTAIN → confidence = min(GCS, 0.50)
Revision penalty: if verdict revised in Round 2 → new_conf × 0.78

Round 1: Independent Analysis

1
Parallel MCP queries

All 4 agents call their MCP servers concurrently (asyncio.gather). Each receives structured JSON evidence specific to this (cell_line, drug, target_genes) tuple. T3 pre-fetches expressed genes from T2 MCP to avoid N individual expression lookups per bypass gene.

2
LLM reasoning → JSON pack

The LLM receives the evidence and produces a verdict, raw confidence, key_findings, reasoning, and (for T3) self_attestation. Format is strict JSON; unparseable outputs default to UNCERTAIN with caveats. T3 also follows the 7-step reasoning protocol before computing self-attestation.

3
GCS overwrites confidence

The system computes GCS from the raw_evidence and key_findings. The LLM's stated confidence is discarded. If verdict = UNCERTAIN, confidence is capped at 0.50. raw_evidence is attached to the pack.

4
Unanimity consensus check

_check_consensus() fires. Returns a verdict only if ALL decisive agents agree on the same verdict. UNCERTAIN agents abstain. T3 quality gates applied first. Any single dissenting decisive agent routes to Round 2.

Consensus Rules Changed: majority → unanimity

Breaking change from previous version: Consensus was changed from “strict majority (3/4 decisive agents agree)” to unanimity among decisive agents. This was critical for the thesis claim: with majority voting, 3/4 decisive agents agreeing was nearly the same as majority vote, undermining the argument that the debate design adds value.

How it works

def _check_consensus(packs: list[EvidencePack]) -> Verdict | None:
    """Return the verdict only when ALL decisive agents agree.
    Consensus requires unanimity — any single dissenting decisive agent routes to debate.
    UNCERTAIN agents do not count as dissent (they abstain).
    T3 quality gates apply before an agent is counted as decisive.
    """
    from src.schemas.evidence_pack import EvidenceTier
    decisive = [p for p in packs if p.verdict != Verdict.UNCERTAIN]
    if not decisive:
        return None  # all abstain → no consensus, go to resolver

    # T3 quality gates: filter out low-quality T3 decisive votes
    filtered = []
    for p in decisive:
        if p.evidence_tier == EvidenceTier.T3_PATHWAY:
            sa = p.self_attestation or {}
            score = sa.get("score") or 0
            if p.verdict == Verdict.RESISTANT and score < 3:
                continue  # T3 RESISTANT with score<3 → treated as abstention
            if p.verdict == Verdict.SENSITIVE and not sa.get("pathway_active", False):
                continue  # T3 SENSITIVE without active pathway → treated as abstention
        filtered.append(p)
    decisive = filtered
    if not decisive:
        return None

    verdicts = {p.verdict for p in decisive}  # unique verdicts
    if len(verdicts) != 1:
        return None  # any dissent → debate
    return decisive[0].verdict

Round 2: Peer Critique Updated

Correction from earlier docs: Verdicts are not locked in Round 2. Agents can revise their verdict under strict conditions. The checklist was also changed from a 4-question binary checklist to a mechanistic relevance score (0.0–1.0 float).

Round 2 fires only when R1 consensus fails. Each agent receives the packs of its 3 peers (labelled A, B, C by tier order, anonymised). Round 2 has two mechanisms that can change outcomes:

1
Mechanistic peer scoring (float, not binary checklist)

Each agent scores each peer on ONE criterion: “Does this peer's key finding have a DIRECT MECHANISTIC CONNECTION to why this drug would or would not work in this specific cell line?”

  • 1.0 = names specific gene/value AND explains mechanistic link to drug action
  • 0.5 = relevant evidence but indirect or population-level only
  • 0.0 = generic, no mechanistic connection, or evidence is for a different target
2
Verdict revision (strict gate)

An agent MAY set verdict_revised=true ONLY IF all three conditions hold:

  1. A peer from a different tier cited a finding mechanistically inconsistent with the agent's conclusion
  2. The agent can name the specific finding: [gene/value] from [tier] contradicts [conclusion] because [mechanism]
  3. The contradiction is mechanistic, not just a different number or different verdict

UNCERTAIN → decisive gate: an agent that was UNCERTAIN in R1 may only become decisive if a peer finding recontextualises its own data — it cannot flip by reinterpreting data it already had. The revision_reason must name the peer's finding, not the agent's own evidence.

Confidence penalty on revision: new_conf = original_conf × 0.78

3
Endorsement aggregation

endorsement(agent_i) = Σj≠i peer_score(j → i) — sum of scores all others gave to agent i. Maximum = 3.0 (3 peers × 1.0 each). If mean endorsement < 0.35 AND peer majority disagrees → verdict revision under peer pressure (penalty: ×0.70).

4
R2 consensus check

After peer critique, _check_consensus() is called again on the updated packs. If unanimity consensus now exists → CONSENSUS_R2 (8 cases = 25.8% in gold standard). Otherwise escalate to AxiomResolver.

AxiomChallenge Mechanism

When R1 has genuine conflict (at least one SENSITIVE and one RESISTANT among decisive agents), the debate engine emits AxiomChallenge objects before peer critique. A higher-tier decisive agent challenges a lower-tier decisive agent that holds an opposing verdict.

@dataclass
class AxiomChallenge:
    challenger_id:      str   # the higher-tier agent (e.g. genomics_agent)
    challenger_tier:    str   # e.g. "T1_STRUCTURAL"
    challenged_id:      str   # the lower-tier agent (e.g. pharmacology_agent)
    challenged_tier:    str   # e.g. "T4_PHARMACOLOGICAL"
    challenger_verdict: str   # SENSITIVE | RESISTANT
    challenged_verdict: str   # the opposing verdict
    argument:           str   # mechanistic argument citing challenger's own key_findings

The challenged agent must provide a specific mechanistic rebuttal from its own modality, or concede:

  • challenge_maintained=true + non-empty rebuttal → agent's verdict stands; gets +1 priority boost in resolver
  • challenge_maintained=false (or empty rebuttal) → agent concedes and adopts challenger's verdict at original_conf × 0.65

AxiomResolver Updated: T1 override threshold

The AxiomResolver fires when R2 consensus fails. It picks a winner by axiom tier priority, with several override mechanisms.

Resolution order

  1. T3 quality gate: filter out T3 packs that don't pass (RESISTANT without score≥3, SENSITIVE without pathway_active=True)
  2. A4 sole-target deletion guard: for multi-target drugs, T1 RESISTANT based on partial homozygous deletion (only one of N targets deleted) is excluded
  3. T1 confidence-weighted override check: if T1 confidence < 0.80 AND all lower tiers unanimously disagree with T1 → use confidence-weighted vote instead of tier-priority
  4. Non-targeted drug demotion: for cytotoxics/broad epigenetics, T1 is demoted to priority 1 (below T4) — somatic mutation evidence is not mechanistically relevant for these drugs
  5. Rebuttal boost: agent that successfully rebutted an AxiomChallenge gets +1 priority
  6. Final tiebreak: max by (effective_priority, peer_endorsement, confidence)

T1 Confidence-Weighted Override

# src/protocols/axiom_resolver.py
T1_OVERRIDE_CONFIDENCE_THRESHOLD = 0.80

Faithfulness Evaluation (LLM-as-Judge) New

Faithfulness measures whether each agent's free-text reasoning is traceable to the data it actually retrieved from its MCP tools — not just whether it performed well on the task.

Why the String-Match Approach Was Wrong

An earlier approach measured faithfulness by checking whether biomarker names from key_findings appeared as substrings in the reasoning text (e.g. does “EGFR” appear in T1's reasoning?). This found 0% hallucination rate. It was wrong because:

  • key_findings is a lossy summary — agents retrieve many values (z_score, AUC, all CIViC descriptions) but only log the most salient one in key_findings
  • A T4 agent reasoning about “z_score=-3.85, AUC=0.52” correctly, but with key_findings.biomarker="EGFR", would count as a miss because “EGFR” isn't in the IC50-focused reasoning
  • It cannot detect an agent claiming “CIViC says Level A sensitive” when the actual CIViC level was C

LLM Judge Design

For each decisive agent in Round 1, the judge receives the full raw_evidence dict (actual MCP tool outputs) and the agent's reasoning text. It decomposes the reasoning into atomic factual claims:

JUDGE_SYSTEM = """You are a faithfulness auditor for a multi-agent biomedical reasoning system.

A 'factual claim' is any assertion that could be true or false based on data:
- Biomarker presence or absence ("EGFR L858R is present")
- Numerical values ("z_score is -3.85", "IC50 ln = -0.11")
- Database classifications ("CIViC classifies T790M as sensitive")
- Pathway membership ("BRAF is in the MAPK/ERK pathway")
- Expression levels ("ERBB2 TPM is 344.5")

NOT a factual claim (exclude):
- Logical conclusions ("therefore the cell line is sensitive")
- Domain knowledge inferences ("T790M is a well-known resistance mechanism")
- Confidence statements ("I am confident that...")

For each factual claim, classify as:
  supported   — directly matches a value in the retrieved evidence
  inferred    — standard biomedical interpretation of supported facts (acceptable)
  unsupported — specific fact assertion NOT present in retrieved evidence

The Real Finding: Cross-Tier Leakage

The key finding from the LLM judge is cross-tier knowledge leakage: T2 and T4 sometimes state facts they couldn't have retrieved from their own tools:

  • T2 states: “NCI-H1975 is an EGFR-mutant line (L858R and T790M)” — T2 only queries CCLE expression data; it knows this from LLM training data, not from its MCP tool call
  • T2 states: “HCC-827 harbors an EGFR exon 19 deletion” — same issue
  • T4 states: “Saos-2 is a p53-null cell line” — T4 only sees IC50 z-scores
  • T4 states: “MCF7 is ER-positive” — not in IC50 database

This is a genuine faithfulness violation: the agent is using training knowledge to contextualise its reasoning rather than only the retrieved data. In these specific cases the facts are correct (these cell lines are indeed what's claimed), but the mechanism is wrong and represents a hallucination risk in edge cases.

Proposed fix: Add explicit instructions to T2 and T4 system prompts: “You ONLY know what your MCP tool calls returned. Do not state cell-line genotype or phenotype facts that are not in your retrieved data.”

The LLM still gets the same data but cannot parse structured fields programmatically. This tests whether JSON structure (field names, nested paths, type-safe values) helps the LLM reason more accurately than equivalent prose.

Case Study: When Pharmacology Alone Fails New

The argument that a pure IC50-lookup system is insufficient rests on concrete mechanistic failures, not aggregate statistics. The 5 cases below are the complete set where T4 (pharmacology agent) had IC50 data and still reached the wrong or ambiguous verdict — while the full 4-agent debate system reached the correct one. Three structurally distinct failure modes emerge.

Failure Mode A — Synthetic Lethality Blindness (2 cases)

IC50 viability assays measure cell death per unit drug concentration in a population of cell lines. They cannot capture context-dependent synthetic lethality — the phenomenon where a DNA repair deficiency (BRCA1/2 loss) makes cells hypersensitive to PARP inhibition independently of target expression. The IC50 population z-score sees HRD-deficient cell lines as “resistant” if the assay was not calibrated to detect synthetic lethality, or if the viability plateau reflects assay duration rather than mechanism.

HCC1937 + Olaparib z_score=1.317, AUC=0.978 RESISTANT (0.424) SENSITIVE BRCA1 homozygous deletion creates HRD; synthetic lethality with PARP inhibition. Population z_score doesn’t capture HRD context — IC50 assay measures cytotoxicity, not repair pathway collapse. T2 (conf=0.895) PARP1=110.4 TPM (target expressed, mechanism active); reasoning explicit: “sensitivity is driven by synthetic lethality in context of BRCA1/2 deficiency, not target overexpression.”
MDA-MB-436 + Olaparib z_score=0.821, AUC=0.970 RESISTANT (0.407) SENSITIVE BRCA1 5′UTR homozygous deletion (functional HRD). Same mechanism as above. T4 interprets high AUC as “poor absolute dose-response” without recognizing cytotoxic assay cannot detect HRD-driven lethality. T3 (conf=0.645) PARP1/2 in active base-excision repair + apoptosis pathways; bypass_check confirms no resistance bypass routes exist. Pathway activation with no escape mechanism → SENSITIVE.

Failure Mode B — Cytostatic Assay Artifact (1 case)

CDK4/6 inhibitors (palbociclib, ribociclib, abemaciclib) are cytostatic: they arrest cells in G1 phase rather than killing them. Standard viability assays (GDSC) measure the fraction of live cells after drug treatment. For cytostatic drugs, sensitive cell lines arrest but remain alive — producing a flat viability curve and a high AUC. T4 interprets high AUC as “no drug response” (resistance), when it is in fact the pharmacodynamic signature of cytostasis. This is a structural artifact of the assay modality, not a measurement error.

Palbociclib causes G1 arrest — cells live but cannot divide. GDSC viability assay reads “alive” as “not killed” = resistant. The AUC of 0.939 is biologically expected for a cytostatic drug in a sensitive line. Failure Mode C — Downstream Bypass Blindness (2 cases)

IC50 population comparison cannot detect mutational bypass routes that activate signaling downstream of the inhibited target. If a cell line has a KRAS or RAS mutation, upstream pathway inhibition (EGFR, PI3K) fails because the oncogenic signal bypasses the drug target. The IC50 measurement reflects the net phenotypic outcome, but because KRAS-mutant lines are common in GDSC, the z_score for EGFR/PI3K inhibitors may be borderline — producing an uninformative T4 abstention. Only T1 (genomics) can see the resistance variant directly from CIViC.
