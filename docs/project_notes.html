Decentralised Multi-Agent System for Cancer Drug Resistance Prediction  ·  Personal reference & recipe book  ·  vertex:gemini-3.1-flash-lite

Project at a Glance

The problem: Given a cancer cell line and a drug, predict whether the cell line will be SENSITIVE, RESISTANT, or UNCERTAIN to that drug — using only molecular evidence retrieved from structured databases, no supervised training.

Training Labels
  • Zero-shot: no fine-tuning, no labelled training data, no embeddings
  • MCP-grounded: each agent queries a dedicated structured database via FastMCP before reasoning — this is the anti-hallucination layer
  • Debate-driven: without the debate protocol, individual agents abstain 87% of the time; the protocol converts uncertainty into grounded collective decisions
  • Interpretable: every verdict comes with a full reasoning chain, cited evidence, and a winning agent + axiom

Ground Truth Labels

Ground truth is derived from CTRPv2 IC50 measurements using a z-score threshold:

IC50 Z-Score (drug-normalised)
z = (ln IC50 − μdrug) / σdrug
μdrug = mean ln IC50 across all cell lines for this drug
σdrug = std dev ln IC50 across all cell lines for this drug

z < −0.5 → SENSITIVE (lower IC50 than average → more sensitive)
−0.5 ≤ z ≤ +0.5 → UNCERTAIN (near population average)
z > +0.5 → RESISTANT (higher IC50 than average → less sensitive)
Caveat: IC50 z-scores are population-level assay measurements. They can be noisy (passage drift, batch effects) and do not always reflect in-vivo sensitivity or clinical outcomes. The system predicts CTRPv2 labels, not clinical response.

The Four Agents

T1 — Genomics Agent (axiom priority: 5)

  • Queries CCLE mutations + CNV for somatic alterations in the drug's target genes
  • Enriches mutations with CIViC drug-specific clinical evidence (live lookup per variant+drug pair)
  • Strong signal: CIViC entry with evidence level A or B linking variant to this specific drug
  • DepMap supplement: when CIViC has no match, queries Chronos CRISPR scores; Chronos ≤ −0.5 = gene essential in this cell line → SENSITIVE signal
  • OpenTargets fallback: when CIViC + DepMap both thin, queries OpenTargets GraphQL API; phase ≥ 3 drug match = strong clinical signal; phase 1–2 = weak signal
  • UNCERTAIN only when all three sources (CIViC, DepMap, OpenTargets) return no actionable evidence

T2 — Transcriptomics Agent (axiom priority: 4)

  • Queries CCLE for mRNA z-scores of the drug's target gene(s)
  • Applies drug mechanism classification: mutation-driven vs expression-driven
  • For expression-driven drugs: z > 1.5 → SENSITIVE (confidence 0.75–0.85); z 1.0–1.5 → SENSITIVE (confidence 0.55–0.70)
  • Silencing gate: z < −2.0 → target absent → RESISTANT
  • For mutation-driven drugs: defers to T1; abstains if T1 is UNCERTAIN

T3 — Pathway Agent (axiom priority: 3)

  • Queries KEGG for pathway membership and bypass gene expression
  • Logic: if pathway is active AND no bypass genes overexpressed → SENSITIVE
  • Bypass check: queries alternative pathway members at z ≥ 1.0
  • Self-attestation gate: must score ≥ 3/4 on 4-question checklist or verdict is demoted
  • Most failure-prone: KEGG doesn’t encode pharmacokinetics or paradoxical feedback

T4 — Pharmacology Agent (axiom priority: 2)

  • Queries CTRPv2/GDSC2 for historical IC50 z-score for this exact (cell line, drug) pair
  • Pre-computed label is returned directly; agent validates and reports
  • Most load-bearing agent in CTRPv2 test set (drove 16/30 verdicts)
  • UNCERTAIN when: no IC50 data available, or |z| ≤ 0.5 (borderline)
  • Lower axiom priority than T1–T3: empirical prior can be overridden by molecular evidence

EvidencePack Schema

Each agent returns one EvidencePack (Pydantic model). This is the unit of information that flows through the debate.

class EvidencePack(BaseModel):
    agent_id:       str           # e.g. "genomics_agent_001"
    cell_line:      str           # e.g. "COLO-205"
    drug:           str           # e.g. "PLX-4720"
    verdict:        Verdict       # SENSITIVE | RESISTANT | UNCERTAIN
    confidence:     float         # GCS score [0.0, 1.0]; UNCERTAIN capped at 0.5
    evidence_tier:  EvidenceTier  # T1_STRUCTURAL ... T4_PHARMACOLOGICAL
    key_findings:   list[Finding] # [{biomarker, value, interpretation, data_source}]
    reasoning:      str           # full LLM reasoning chain
    caveats:        list[str]
    conflict_flags: list[str]
    peer_scores:    dict          # {"A": 0.75, "B": 1.0, ...} filled after Round 2
    self_attestation: dict | None # T3 only: {"score": int, "checks": [bool,...]}
    data_status:    str | None    # "data_found" | "target_wild_type" | "cell_line_missing" ...

GCS Formula (Grounded Confidence Score)

The GCS replaces the LLM’s raw self-reported confidence with a structured score computed from the evidence. It is calculated after the LLM returns its pack, overwriting whatever the LLM said its confidence was.

Grounded Confidence Score
GCS = 0.40 · H  +  0.30 · E  +  0.20 · T  +  0.10 · S

H (Hit rate) = fraction of cited biomarkers found in MCP evidence text
   = count(key_findings where biomarker appears in evidence_raw JSON) / len(key_findings)
   If no key_findings listed → H = 0.0

E (Evidence completeness) = 1.0 if MCP returned any non-empty data, else 0.0
   (binary: did the database have anything at all for this query?)

T (Tier weight): T1=1.0, T2=0.8, T3=0.6, T4=0.4, T5=0.2

S (Signal strength) = LLM’s raw self-reported confidence, clamped to [0, 1]

UNCERTAIN cap: if verdict = UNCERTAIN → confidence = min(GCS, 0.50)

Known calibration issue: High E (data returned) + high H (biomarker cited) can produce high GCS even when the evidence is irrelevant to the resistance mechanism. This creates high-confidence wrong predictions when one agent commits and others abstain. Proposed fix: apply a ×0.85 singleton penalty when only one agent is decisive.

Round 1: Independent Analysis

1
Query MCP

Each agent independently calls its MCP server with the (cell line, drug) pair and receives structured JSON evidence.

2
LLM reasons → returns JSON pack

The LLM receives the evidence and produces a verdict, raw confidence, key_findings, reasoning, and (for T3) self_attestation. Format is strict JSON; unparseable outputs default to UNCERTAIN.

3
GCS overwrites confidence

The system computes GCS from the evidence and key_findings — the LLM’s stated confidence is discarded. If verdict = UNCERTAIN, confidence is capped at 0.50.

4
Consensus check

The 4 packs are passed to _check_consensus(). If a strict majority of decisive agents agree (and no T1 veto fires), the result is returned as CONSENSUS_R1 and Round 2 is skipped.

Round 2: Peer Critique

Round 2 fires only when R1 consensus fails. Verdicts are locked — agents cannot change their SENSITIVE/RESISTANT/UNCERTAIN call. They can only adjust confidence by ±0.10 and score peers.

1
Each agent reviews peers

Every agent receives the packs of its 3 peers (labelled A, B, C anonymously by tier order). It applies a tier-specific 4-question binary checklist to each peer’s reasoning text. Score = (# yes answers) / 4 ∈ [0.0, 1.0].

2
Confidence adjustment

Each agent may adjust its own confidence by at most ±0.10 based on what peers found. UNCERTAIN verdict confidence still capped at 0.50.

3
Endorsement aggregation

endorsement(agent_i) = Σj≠i peer_score(j → i) — sum of scores all other agents gave to agent i. Max possible = 3.0 (3 peers × 1.0 each).

4
R2 consensus check

After peer critique, _check_consensus() is called again on the updated packs. If consensus now exists → CONSENSUS_R2. Otherwise escalate to AxiomResolver.

Peer Checklists (per tier)

The checklist applied to a peer depends on the peer’s evidence tier, not the reviewer’s. Each question is answered true/false based strictly on what the peer’s reasoning text actually states.

T1 Structural checklist
  • Q1Did this peer name a specific mutation or CNV in the drug target gene (not just ‘no mutation found’)?
  • Q2Did this peer cite a CIViC/OncoKB entry or known functional consequence linking the variant to drug response?
  • Q3Did this peer confirm the variant is somatic (not germline or unclassified)?
  • Q4Does the variant’s functional direction (gain-of-function / loss-of-function) logically support the verdict given?
T2 Transcriptional checklist
  • Q1Did this peer report a specific numeric z-score for the target gene expression?
  • Q2Is the expression level (overexpressed / silenced / normal) consistent with the verdict direction?
  • Q3Did this peer explicitly account for whether this drug is expression-driven vs mutation-driven?
  • Q4Did this peer name at least one specific gene with its z-score value (not just ‘expression is high’)?
T3 Pathway checklist
  • Q1Did this peer name at least one specific bypass gene (not just ‘bypass_exists=true’)?
  • Q2Did this peer report the pathway activity score or fraction of expressed pathway genes?
  • Q3Does the bypass gene mechanistically connect to resistance for this specific drug class?
  • Q4Is the bypass gene distinct from the primary drug target gene?
T4 Pharmacological checklist
  • Q1Did this peer report a specific IC50 z-score value (not just ‘no data’ or ‘uncertain’)?
  • Q2Did this peer explicitly state the pre-computed IC50 label (SENSITIVE/RESISTANT/UNCERTAIN)?
  • Q3Does the historical IC50 label match or logically support the verdict given?
  • Q4Did this peer acknowledge that T4 pharmacological evidence can be overridden by T1–T3 molecular evidence?
The T3 self-attestation checklist (used internally by T3 to gate its own decisiveness) uses the same 4 questions as the T3 peer checklist above. If T3’s self-score < 3, its verdict is demoted to UNCERTAIN in the consensus check — even if it said SENSITIVE or RESISTANT.

Consensus Rules

_check_consensus() flowchart. Called after R1 and again after R2. T3 self-attestation gate replaced the old “T1+T2 both UNCERTAIN” quorum rule.

Key Rules in Plain English

  • Strict majority: n decisive votes for the same verdict must exceed half the total decisive pool. With 2 decisive agents, both must agree. With 3, at least 2 must agree.
  • T3 self-attestation gate: T3 pathway agent is only counted as decisive if its internal 4-question checklist score ≥ 3. Otherwise it’s treated as UNCERTAIN in the consensus check (even if it said SENSITIVE/RESISTANT).
  • T1 veto: If T1 is decisive and ALL T1 agents disagree with the majority verdict → consensus returns None (escalate). Protects against structural evidence being overridden by weaker tiers.
  • UNCERTAIN agents: never counted in the decisive pool for consensus. They may still participate in peer critique (R2) and influence endorsement scores.

AxiomResolver

Fires when neither R1 nor R2 consensus is reached. Acts as a deterministic tiebreaker.

Main sort key (no weak-T1 situation)

Resolver sort key — picks winner = argmax over candidates
winner = argmaxp ( endorsement(p), axiom_weight(p), GCS(p) )
Tie broken left-to-right: endorsement first, then axiom tier, then confidence

endorsement(p) = total peer score given to agent p across all peer reviewers
axiom_weight: T1=5, T2=4, T3=3, T4=2, T5=1
GCS(p) = agent p’s grounded confidence score

candidates = decisive agents (verdict ≠ UNCERTAIN); falls back to all agents if none decisive

Weak T1 exception (confidence-weighted vote)

When: T1 is decisive but confidence < 0.70 (T1_OVERRIDE_CONFIDENCE_THRESHOLD) AND all lower-tier agents unanimously hold a different verdict.
Then: Instead of T1 winning by axiom priority, use confidence-weighted vote across all candidates. Winning verdict = the one with highest summed confidence. This prevents a low-confidence T1 wild-type call from overriding a unanimous T2+T3+T4 signal.

Confidence decay (applied to non-winners)

Confidence decay for losing agents
new_conf = old_conf × (1 − 0.15)
Applied only to agents whose verdict differs from the winner’s verdict
Agents who abstained (UNCERTAIN) or agreed with winner: confidence unchanged
CONFIDENCE_DECAY_PER_FLIP = 0.15 (src/schemas/axiom_rules.py)

Final confidence (after resolver)

Final confidence computation
final_conf = mean( adjusted_conf for all agents )
Uses ALL agents’ adjusted confidence (after decay), not just the winner
For CONSENSUS paths: mean( conf of agents whose verdict = winning verdict )

Why Custom? (No ADK / LangChain / LangGraph)

The short answer: every mature framework assumes agents are interchangeable tool-callers coordinated by an orchestrator. DMAS needed structured epistemic authority — where evidence tier, not call order or confidence vote, determines who wins a disagreement. No framework supported that out of the box.

Left: what a framework gives you. Right: what DMAS actually needed. The gap between them is why all debate logic was written from scratch.

The core mismatch

All frameworks treat multi-agent conflict as a routing or scheduling problem: who speaks next, whose output feeds into whom, how to retry on failure.


DMAS treats conflict as an epistemological problem: which evidence type has higher causal authority, and how do you prevent weaker evidence from overriding stronger evidence just because it outnumbers it?

Framework model
WHO speaks & WHEN — a scheduling concern
DMAS model
WHAT carries more epistemic weight — a domain knowledge concern
Why this matters
No amount of routing cleverness makes a majority-vote resolver safe when a 3-to-1 IC50 consensus can override a confirmed BRAF V600E mutation

Framework-by-framework evaluation against the DMAS debate protocol. LangGraph is technically usable as a routing scaffold but doesn’t reduce the amount of custom protocol code written.

The LangGraph counter-argument (and why it still doesn’t help enough)

  • What LangGraph does give you: graph state persistence, conditional edge routing, retry logic on node failure, Langsmith tracing
  • What you’d still write from scratch inside the nodes: GCS formula, T3 self-attestation gate, T1 veto check, strict-majority consensus, all 4 peer checklists, AxiomResolver sort key, confidence decay — i.e., the entire debate protocol
  • What you’d additionally fight: LangGraph’s state serialisation format, its Checkpoint API, and its assumption that all edges carry the same typed state object — whereas our packs are heterogeneous (T3 has self_attestation, others don’t)
  • Net conclusion: Using LangGraph would mean writing the same 600 lines of protocol code, plus ~200 lines of graph wiring, plus debugging framework-specific state issues. Plain Python is strictly less code for the same result.

Worked Example: COLO-205 + PLX-4720

A clean BRAF V600E case showing how R1 consensus works when T1 has definitive evidence.
